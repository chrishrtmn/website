The last version of this site shipped in 2020 on Next.js 12. It had skewed gradient bands, a ticker of company names, and a stat that read "11, volume cranked." It was fine. It was also four years old, said "front-end developer" in a way that undersold the work, and loaded a React runtime to render a page that never changed.

This one is different in three ways.

## The word

Every version of this site I sketched over the last two years had the same word on it: OPE. It's what you say in Ohio when you bump into someone, almost drop something, or need to squeeze past. It's an apology and a greeting at once. For a personal site it does a lot of work in three letters: it tells you where I'm from, it tells you I don't take the exercise too seriously, and it is impossible to confuse with anyone else's portfolio.

The first attempts animated it. Glitch effects, letters falling, a clip of someone bumping into the camera. All of it read as a bit. The version that stuck is the quietest: a single word set so large it's cropped by the viewport, a neon column with a plain-text ledger of facts, and one line underneath. The motion is a clip-path reveal and a column slide that play once per session. After that the page loads in its final state.

## Astro over Next.js

The site has about eight routes, a handful of MDX posts, and two tiny endpoints (local weather, latest commit). Nothing needs server components or per-request rendering. Next.js 15 would ship roughly 85 KB of framework JavaScript to a page that needs maybe 10.

Astro ships none by default. The hero, the tickers, the work rows, the experience ledger: all HTML and CSS. JavaScript hydrates four things, and only when they're on screen: the command menu, the motion toggle, a clock, and the weather line. Those run on Preact, so the whole page is around 11 KB of JS compressed. The fonts weigh more than the code.

LinuxStatistics already runs on Astro, so the stack was familiar and the tooling carried over.

## Three seconds

The one hard constraint I set before any design work: a cold load should settle in under three seconds on a mediocre connection, and the largest paint should be text, not an image or a video. That rule killed a few ideas (a hero video, a live data wall) and shaped the rest. Fonts are subset to Latin and preloaded. There are no hero images. The intro animation starts from CSS before any script runs, so there's no flash of the final layout before the first frame.

Lighthouse runs on every preview deploy and fails the build if the budget slips.

## Motion policy

Everything that moves on this site keys off one attribute on the `html` element: `data-motion`. It's set before paint from your OS preference or the switch in the header. Off means the hero renders its last frame, the tickers become a grid, the tickets don't deal in, and nothing transitions. On means the opposite, with one rule: nothing triggered from the keyboard animates. The command menu opens instantly.
